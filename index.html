Problem 1: Precomputed Hash Table Storage & Rainbow Tables

Examiners: Prof. Walaa Khaled & Dr. Alshaimaa Abo-alian

Topic: Cryptographic Storage & Hashing
Exam Scenario:

An attacker aims to construct a pre-computed table for cracking 8-character passwords which are composed of the 62 alphanumeric characters (A-Z, a-z, 0-9) and hashed by SHA-256.

a

Calculate the total storage space required to store the table. (3 marks)

Step 1: Character Set Size (N)
  • • Uppercase English letters (A–Z): 26
  • • Lowercase English letters (a–z): 26
  • • Decimal Digits (0–9): 10
  • Total characters (N) = 26 + 26 + 10 = 62
Step 2: Keyspace (Total Passwords, K)

For passwords of length L = 8:

K = NL = 628
K = 218,340,105,584,896 passwords
≈ 2.1834 × 1014 passwords
Step 3: Size of Each Entry

A precomputed lookup table stores pairs of (Password, Hash):

  • • Plaintext password (8 chars): 8 bytes
  • • SHA-256 Digest (256 bits): 32 bytes (raw binary)
  • Total size per entry = 8 + 32 = 40 bytes

*Note: If stored in hex text format, SHA-256 is 64 hex characters = 64 bytes (8 + 64 = 72 bytes/entry). Both are accepted by examiners.

Step 4: Total Storage Space
Total Bytes = 218,340,105,584,896 × 40 bytes
= 8,733,604,223,395,840 Bytes
• In Terabytes (TB): 8,733,604,223,395,840 / 10244 ≈ 7,943.17 TB
• In Petabytes (PB binary): 7,943.17 / 1024 ≈ 7.76 PB (or 8.73 PB in decimal 1015)
📌 Official Answer: Total storage required is 8.73 Petabytes (decimal SI) or 7.76 Petabytes (7,943 TB binary). (If 72 bytes/entry hex is assumed, storage is ~15.72 PB).
b

Discuss how the attacker can reduce storage requirements of the precomputed table. (3 marks)

The attacker can drastically reduce storage requirements by implementing Time-Memory Trade-Off (TMTO) techniques, most notably Rainbow Tables (or Hellman's hash chains):

1. Hash Chains & Reduction Functions

Instead of saving all pairs, chains are formed by alternating between the hash function H and a reduction function R that maps 256-bit hashes back into 8-character plaintexts: P₀ → H(P₀) → R₁(H) → P₁ → ... → Pₘ

2. Store Only Chain Endpoints

The attacker only saves the Start Password (P₀) and the End Password (Pₘ) on disk! All intermediate m-1 passwords and hashes are discarded, reducing required disk space by a factor of m (e.g. 10,000× compression).

3. Different Reduction Functions

Rainbow tables use a different reduction function (R₁, R₂, ..., Rₘ) at each position in the chain, eliminating the chain collisions and merges that plagued Hellman's original single-function chains.

c

Identify effective mitigation strategies if an attacker employs techniques to reduce storage requirements. (5 marks)

1. Cryptographic Salting (#1 Defense)

Append a unique, random string (≥16 bytes) to each password before hashing: Hash(Salt || Password). Because every user has a distinct salt, precomputed tables become completely useless—an attacker would have to compute a multi-petabyte table for every single individual salt.

2. Slow Key Stretching Hashes

Replace fast general hashes (like SHA-256) with slow, resource-intensive algorithms such as Argon2id, bcrypt, or PBKDF2. High iteration counts and RAM memory hardness make generating reduction chains computationally infeasible.

3. Secret Pepper

A system-wide secret key stored outside the database (e.g. in a Hardware Security Module - HSM or secret vault). Even if attackers steal the database hashes and salts, they cannot generate tables without knowing the secret pepper.

4. Enforce Password Length & Entropy

Enforce a minimum length of 12 to 16 characters. Increasing length exponentially explodes the keyspace (62¹² ≈ 3.22 × 10²¹), making precomputed tables physically impossible to store even with rainbow compression.

5. Multi-Factor Authentication (MFA) & Rate Limiting

Even if an attacker cracks a password offline, MFA (TOTP / FIDO2 security keys) blocks unauthorized account access without the physical second factor. Account lockouts and exponential backoff prevent online brute-force guessing.

Problem 2: Relational Database Access Control Matrix & SQL DCL

Examiners: Prof. Walaa Khaled & Dr. Alshaimaa Abo-alian

Topic: Discretionary Access Control & SQL
Given Access Control Matrix:
User / Resource Table1 Table2 Table3
Alice Read, Write Read None
Bob Read (column 3 only) None Write
Charlie Write Read Read
a

Identify Model & Drawbacks (3 marks)

Identified Model: Discretionary Access Control (DAC), implemented via an Access Control Matrix.

Main Drawbacks:
  • Vulnerability to Trojan Horses: A malicious script run by Alice inherits her rights and can leak Table1 data without detection.
  • No Information Flow Control: Cannot prevent secondary dissemination once a user reads data.
  • Scalability Limitations: N×M matrix becomes sparse, difficult to update and audit as tables grow.
b

List Other Access Control Models (2 marks)

  • • Mandatory Access Control (MAC): Centralized, non-discretionary model based on fixed security clearances and classification labels (e.g. Bell-LaPadula, Biba).
  • • Role-Based Access Control (RBAC): Permissions assigned to job roles; users assigned to roles (least privilege & separation of duties).
  • • Attribute-Based Access Control (ABAC): Dynamic policies evaluating subject attributes, resource attributes, and environment conditions (time, IP, location).
c

Generate Corresponding Access Control Lists (ACLs) (3 marks)

Access Control Lists (ACLs) represent the columns of the matrix (object-centric lists attached to each table):

ACL(Table1)
  • • Alice: {Read, Write}
  • • Bob: {Read (column 3)}
  • • Charlie: {Write}
ACL(Table2)
  • • Alice: {Read}
  • • Charlie: {Read}
  • (Bob: None)
ACL(Table3)
  • • Bob: {Write}
  • • Charlie: {Read}
  • (Alice: None)
d

Using SQL statements, implement the access control policies in the ACLs. (5 marks)

-- ==========================================================
-- 1. Policies for Alice
-- ==========================================================
GRANT SELECT, INSERT, UPDATE, DELETE ON Table1 TO Alice;
GRANT SELECT ON Table2 TO Alice;

-- ==========================================================
-- 2. Policies for Bob
-- ==========================================================
-- Table1: Read column 3 only (Column-level grant)
GRANT SELECT (col3) ON Table1 TO Bob;
GRANT INSERT, UPDATE, DELETE ON Table3 TO Bob;

-- ==========================================================
-- 3. Policies for Charlie
-- ==========================================================
GRANT INSERT, UPDATE, DELETE ON Table1 TO Charlie;
GRANT SELECT ON Table2 TO Charlie;
GRANT SELECT ON Table3 TO Charlie;
e

Explain the difference between CASCADE and RESTRICT in a REVOKE statement. (2 marks)

REVOKE ... CASCADE

Recursive Revocation: If the target user was given privileges WITH GRANT OPTION and granted those privileges to subsequent users, CASCADE recursively revokes the privilege from that user and all dependent downstream grantees (propagates down the grant tree).

REVOKE ... RESTRICT

Protected Safe Revocation: Prevents revocation if any dependent grants exist. If the target user granted privileges to others using WITH GRANT OPTION, the REVOKE ... RESTRICT statement aborts immediately with an error, forcing the administrator to revoke dependencies manually.

Problem 3: University File System Access Control & Bell-LaPadula (BLP)

Examiners: Prof. Walaa Khaled & Dr. Alshaimaa Abo-alian

Topic: Mandatory Access Control (MAC)
Exam Scenario:

A university file system has the following access control policy:
• Professor Smith owns FileA. Professor Smith wants Student1 to read FileA only and wants TA1 to read and write FileA.
• Student2 owns FileB and wants Professor Smith to read FileB.

A

Represent this access control scenario using ACM, ACL, and C-List (3 marks)

1. Access Control Matrix (ACM)
Subject / Object FileA FileB
Professor Smith Own, Read, Write Read
TA1 Read, Write None
Student1 Read None
Student2 None Own, Read, Write
2. Access Control Lists (ACLs - Columns)

Object-centric lists storing authorized users per file:

  • • ACL(FileA): { Prof. Smith: (Own, R, W), TA1: (R, W), Student1: (R) }
  • • ACL(FileB): { Student2: (Own, R, W), Prof. Smith: (R) }
3. Capability Lists (C-Lists - Rows)

Subject-centric tickets carried by each user:

  • • C-List(Prof. Smith): [ (FileA: Own, R, W), (FileB: R) ]
  • • C-List(TA1): [ (FileA: R, W) ]
  • • C-List(Student1): [ (FileA: R) ]
  • • C-List(Student2): [ (FileB: Own, R, W) ]
B

Name Model & Identify Advantages / Disadvantages (3 marks)

Model Name: Discretionary Access Control (DAC). The creator/owner of a file possesses total discretion to define, grant, or revoke permissions.

Advantages
  • High flexibility: Owners manage permissions without waiting for IT administrators.
  • Simple, low overhead, and supported natively by all major operating systems.
Disadvantages
  • Security depends entirely on user vigilance (risk of over-permissive grants).
  • Vulnerable to Trojan horses leaking sensitive data via owner permissions.
C.1

Bell-LaPadula (BLP) Access Evaluation (All 8 Combinations) (4 marks)

Bell-LaPadula (BLP) Core Axioms:
• Simple Security Property (ss-property): No Read Up (NRU)
Subject S can READ object O iff Clearance(S) ≥ Classification(O).
• *-Property (Star Property): No Write Down (NWD)
Subject S can WRITE/Append object O iff Clearance(S) ≤ Classification(O).
Clearance Hierarchy: Top Secret (TS) > Secret (S) > Confidential (C) > Unclassified (U)
User (Clearance) File (Class.) READ Allowed? WRITE Allowed? BLP Rule Justification
Professor Smith (TS) FileA (S) Allowed Denied TS ≥ S (Read Up satisfied); TS > S violates No Write Down (would leak TS info into S file).
Professor Smith (TS) FileB (C) Allowed Denied TS ≥ C (Read Up satisfied); TS > C violates No Write Down (would leak TS info into C file).
TA1 (S) FileA (S) Allowed Allowed S = S (Equal level satisfies both ss-property S ≥ S and *-property S ≤ S).
TA1 (S) FileB (C) Allowed Denied S ≥ C (Read Up satisfied); S > C violates No Write Down (cannot write down to lower level).
Student1 (C) FileA (S) Denied Allowed C < S violates No Read Up; C ≤ S satisfies No Write Down (blind write / append up allowed).
Student1 (C) FileB (C) Allowed Allowed C = C (Equal level satisfies both ss-property C ≥ C and *-property C ≤ C).
Student2 (U) FileA (S) Denied Allowed U < S violates No Read Up; U ≤ S satisfies No Write Down (blind write / append up allowed).
Student2 (U) FileB (C) Denied Allowed U < C violates No Read Up; U ≤ C satisfies No Write Down (blind write / append up allowed).
C.2

Explain the main difference between MAC and DAC (2 marks)

Mandatory Access Control (MAC)
  • Centralized Authority: Governed strictly by system-wide security policies.
  • Classification Labels: Based on security clearances (subjects) and classification levels (objects).
  • Immunity: Even the file creator CANNOT alter access rights. Guarantees protection against Trojan horse leaks.
Discretionary Access Control (DAC)
  • Owner Authority: Governed entirely by individual resource owners at their own personal discretion.
  • Identity-Based: Access is based on user identity or group membership (via ACLs or matrix).
  • Vulnerable: Owners can freely propagate rights to others; susceptible to unauthorized data exfiltration.
